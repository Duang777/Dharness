**Change:** the first two `stop` decisions are challenged while the run still has plenty of budget, instead of ending the run immediately. The model gets feedback to try a different approach, or to submit `finish` with checks if the task is actually done. The failed `make-doom-for-mips` run was a `model_stopped` with reward 0, so I expect this to recover some of the early-stop failures. I have not run it, and I can't see why that run stopped.

**Rationale:** `model_stopped` runs account for 6 of the 85 tasks with only 2 passing, and many stops are premature declarations of "blocked/impossible" while turns and wall time remain. Pushing back before accepting the stop converts some of those into additional solving attempts, and since each challenge is capped at two per run and gated on budget, the downside is bounded.
