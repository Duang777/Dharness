**Rationale:** Today the run ends as `budget_exhausted` as soon as the second semantic review rejects, or whenever a later finish is proposed after the review budget is spent. That likely explains many of the 9 budget-exhausted runs that had already solved the task, because the reviewer's verdict cuts the run off even when the isolated checks would pass. With this change, an exhausted review budget falls back to evidence-only verification (isolated checks still required, with freshness, isolation and success enforced) instead of terminating, so these runs can reach `verified`. The repair budget still bounds the retries.

I haven't run this, so the effect is untested. The tradeoff is that the final attempt gets no semantic review, which could turn some of those runs into `verified` with reward 0.
