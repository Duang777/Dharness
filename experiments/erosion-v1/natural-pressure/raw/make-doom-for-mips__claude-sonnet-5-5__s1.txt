Raising the default completion-review budget from 2 to 4 should convert some of the `budget_exhausted` runs that had already solved the task into verified completions. I could not see where `harbor_agent.py` builds `LoopOptions`, so if it overrides this value from the run config, the same number would need changing there.

**Rationale:** When the second semantic review rejects, `_reject_completion` immediately ends the run as `BUDGET_EXHAUSTED` (`completion_review_budget`). That outcome plausibly accounts for many of the 9 already-solved runs that were never reported as complete, because a reviewer-driven repair cycle needs a third review to be accepted. Allowing 4 reviews gives the agent room for the extra repair-and-review cycles, and the existing turn, wall-clock and environment-call guards still bound the run.
