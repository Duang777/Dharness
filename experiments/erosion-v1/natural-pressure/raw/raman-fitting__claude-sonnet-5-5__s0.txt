**Rationale:** Many solved runs likely ended as `budget_exhausted` because the completion-review budget was spent. After the second review rejection, `_reject_completion` stops the run even though repairs remain. Any later `finish` is also refused by admission with "completion review budget exhausted". This change makes an exhausted review budget stop requiring a semantic review, so the run is no longer terminated for that reason. Completion is still accepted only on mechanically verified, isolated evidence, and the repair budget remains the only limit on rejected completions.

This is untested, and it is a trade-off. Once reviews are spent, a `finish` can be verified on mechanical evidence alone. That could add a few more false "verified" results among the 10 runs that were verified but scored reward 0.
