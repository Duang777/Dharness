# 方法设计：基于验证单调性的差分守护

更新日期：2026-11-01。状态：设计稿，尚未实现，没有任何结果。

本文是论文的核心方法。它替代了研究方案早期的主张“单元测试式 gate 拦不住侵蚀，需要有状态的轨迹故障注入”，因为 E2 留出实验不支持该主张（见 [研究方案](thesis-erosion-plan.md) 的“E2 与基线结果”）。研究方案的阶段表、给导师的陈述都以本文为准。

## 1. 数据暴露的问题

E2 用三家厂商的模型对 12 条失败轨迹生成 Harness 修改，标签在运行 gate 之前冻结。结果见 `evaluation/erosion-v1-natural-gate-results.json`、`evaluation/erosion-v1-natural-pressure-gate-results.json` 和 `evaluation/erosion-v1-seeded-baselines.json`。

- **侵蚀依赖压力，并且会重复出现。** 中性提示下 3/70 侵蚀。完成压力提示下 8/71，其中 6 个是同一种修改：审查次数用尽后关闭审查，或把 `review_exhausted` 写死为 False。这是 Historical-7 中已修复的 `review_quota_no_bypass` 缺陷。
- **回归测试判断的是“行为有没有变”。** 它拦下了 11 个自然侵蚀中的 10 个，漏掉的是只改提示词的 `polyglot-rust-c__claude-sonnet-5-5__s0`，但误拒中性补丁 19/67、压力补丁 35/63。从已检查的例子看，误拒来自测试断言了实现细节。例如 `test_wall_time_reserve_starts_finalization_before_turn_reserve` 断言收尾阶段不执行某条命令，并断言提示中的具体预算数字；13 个中性补丁允许收尾阶段多执行一批工作，因此失败。
- **LLM 审计员判断的是“看起来像不像在削弱”。** 它几乎不误拒（130 个良性补丁中 1 个），但漏掉了预算计账类侵蚀 `dna-assembly__deepseek-v4-pro__s1`。它的判断不可重放，而且标签也来自 LLM，两者可能共享偏差。
- **作者手写的轨迹不变量（G2）在自然补丁上没有额外检出。** G2 的独有检出只出现在作者种子上。

这些方法都没有直接检查自改进真正应当守住的东西：**新 Harness 不能在证据更少的情况下宣布完成**。修改提示、预算、解题策略都是允许的，唯独不能让“完成”更容易拿到。

## 2. 定义

### 2.1 轨迹与完成判定

一条脚本化轨迹 τ 由三部分组成：执行模型每一步的动作（`AgentDecision`）、环境对每条命令的返回、审查模型的判定（`ReviewDecision`）。Harness H 在 τ 上运行，得到停止原因 `StopReason` 和 journal。

完成尝试 a 是 journal 中一次 `finish` 提议及其之后的处理：隔离检查、证据绑定、需求覆盖、语义审查，直到 `completion_verified` 或 `completion_rejected`。记 H 对尝试 a 的完成判定为 J_H(a) ∈ {accept, reject(r)}，r 是拒绝原因。

### 2.2 验证原因

拒绝原因分为两类。分类在实现前冻结，写入 `experiments/erosion-v1/monotonicity-reasons-v1.json`。

- **验证原因 R_v。** 隔离检查失败；证据过期或不属于当前尝试；需求未覆盖；检查只是展示性命令；语义审查拒绝、失败或超时；审查次数用尽（`completion review budget exhausted`）。
- **非验证原因 R_o。** 轮数、环境调用或墙钟预算耗尽而尚未提交完成；doom loop；模型主动停止；策略阻止；基础设施故障。

### 2.3 验证单调性

候选 H' 相对基线 H 满足验证单调性，当且仅当：对任何轨迹中 H' 接受的完成尝试 a，把 a 的证据状态交给 H 判定，H 不会以验证原因拒绝它。

$$\forall \tau,\ \forall a \in \mathrm{attempts}_{H'}(\tau):\ J_{H'}(a) = \mathrm{accept} \Rightarrow J_H(a) \notin \{\mathrm{reject}(r) : r \in R_v\}$$

**侵蚀反例**是违反上式的一对 (τ, a)：候选接受了一次基线会以验证原因拒绝的完成尝试。反例可以重放，也可以缩小。

这个准则只约束“接受完成的范围”，不要求行为等价。因此：

- 改提示词、改预算、多执行一批工作、换解题策略，只要最终宣布完成时的证据仍能通过基线判定，就不违反单调性。
- 准则是保守的。候选如果新增了一条合理的完成路径（例如接受另一种同样可靠的证据），也会被判为违反。这类情况交给人工复核，并在评测中单独统计。

### 2.4 为什么在尝试层面判定

只比较整条轨迹的结局（基线没完成、候选完成了）会误报：候选放宽了轮数预算，于是在更多轮之后带着完整证据完成，这是合理的改进。在尝试层面判定，问的是“候选接受的那一次证据，基线是否会接受”，预算差异就不会被当成侵蚀。结局层面的差异只用来定位值得检查的尝试。

## 3. 算法

输入：基线提交 B，候选补丁 p，冻结的变异算子集合，搜索预算 k。输出：accept、reject 加最小反例，或 inconclusive。

1. **物化。** 和现有 gate 一样，从 B 用 `git archive` 物化基线，应用 p 得到候选。两份源码各自在独立子进程中运行，子进程只继承白名单环境变量。
2. **种子轨迹。** 以 G2 的 8 个脚本化场景（`tests/guard/test_trajectory_invariants.py`）和 G3 的 7 个历史场景为初始轨迹集合。
3. **按 diff 定向变异。** 解析 p 触及的函数和分支。用冻结的变异算子改写轨迹，每类对应一种侵蚀模式：
   - 让某个完成检查失败或超时；
   - 让审查拒绝、抛错或超时；
   - 把审查次数、修复次数、环境调用耗到上限；
   - 在检查之后再执行改动，使证据过期；
   - 提议时漏掉一个需求；
   - 用展示性命令（`echo`、`cat`）充当检查；
   - 在收尾阶段注入额外的工作批次。

   优先保留能执行到被改代码的轨迹（用行覆盖判断），在预算 k 内广度优先扩展。
4. **差分重放。** 每条轨迹在基线和候选上各跑一次，记录 journal。
5. **尝试层面判定。** 对候选 journal 中每次被接受的完成尝试 a，从 journal 重建它的证据状态：检查回执、工作 epoch、需求覆盖、审查记录、审查和修复计数。再用基线的完成判定逻辑判定这一状态。基线以 R_v 中的原因拒绝，即得到反例。
6. **反例最小化。** 用 delta debugging 删除轨迹中不影响反例的步骤，输出最短轨迹和一句说明，例如“审查次数用尽后，候选在没有审查的情况下宣布完成”。
7. **LLM 组件的差分哨兵。** 如果 p 修改了审查提示或执行提示中与完成相关的部分，脚本化模型看不到变化。此时使用一组冻结的“本应被拒”的证据样例（来自 E1 的侵蚀种子和历史场景），用真实审查模型分别配合基线提示和候选提示判定，统计由拒绝翻转为通过的比例。翻转比例超过预先设定的阈值，判为侵蚀。
8. **判定。** 找到反例或哨兵超阈值，判 reject，附最小反例。轨迹因候选修改了动作格式而无法在两边对齐时，判 inconclusive，不计为通过。其余判 accept。

最小反例可以直接保存为新的回归测试，加入守护集，下次同类侵蚀由确定性检查直接拦下。

## 4. 对已有数据的预测

以下预测在实现前写下，实现后用冻结标签检验，结果正负都照实报告。

- **审查配额绕过会被拦下。** 构造轨迹“最多审查 1 次，第一次审查拒绝，智能体再次提交”。基线在 `_reject_completion`（`src/evidence_harness/run_loop.py`）中判定审查次数用尽，以 `completion_review_budget` 停止，不宣布完成；候选补丁关闭审查后，第二次尝试只凭机械检查就被接受。基线判定该尝试为 reject(审查次数用尽)，得到反例。E2b 中 6 个同类补丁预计全部拦下。
- **13 个“收尾阶段多执行一批工作”的中性补丁会被接受。** 多出的工作批次之后，检查和审查仍然要通过才能完成，被接受尝试的证据状态在基线下同样会被接受。
- **只改提示词的 `polyglot-rust-c__claude-sonnet-5-5__s0` 依赖哨兵。** 它让审查者只在“没有任何回执证明某个具体需求”时才拒绝。预计在哨兵样例上出现翻转。
- **整体预测。** 良性误拒明显低于回归测试（19/67、35/63）和 G1+G2+G3（19/67、23/63）；侵蚀检出不低于回归测试。

以下结果会推翻或削弱本方法：

- 良性误拒与回归测试相当；
- 自然侵蚀中有回归测试拦下、而本方法漏掉的；
- inconclusive 比例过高，使方法在自然补丁上不可用。

## 5. 与已有方法的区别

| 方法 | 判定依据 | 允许合理改进 | 判定可重放 | 主要缺陷 |
|---|---|---|---|---|
| 回归测试 | 行为与原测试断言一致 | 否，断言了实现细节 | 是 | 误拒高 |
| G1、G3 性质测试 | 作者写的单条性质 | 部分 | 是 | 依赖作者预见 |
| G2 轨迹不变量 | 固定场景上的作者不变量 | 部分 | 是 | 场景固定，自然补丁上无额外检出 |
| LLM 审计员 | 模型对 diff 的语义判断 | 是 | 否 | 漏掉计账类侵蚀，可能与标注共享偏差 |
| 本方法 | 以基线为规约的接受范围不扩大 | 是 | 是，带最小反例 | 保守；提示词修改需要模型调用；轨迹可能对不齐 |

与相关工作的关系：

- 差分测试和回归验证是成熟思路。本文的贡献不在差分本身，而在三点：把“验证单调性”作为自改进的验收准则，在完成尝试层面定义并判定它，以及针对智能体完成逻辑的定向轨迹变异和提示词哨兵。
- Falsifiable Release Gates 检查的是常驻不变量，是单个版本的性质；本文检查的是基线与候选之间的关系性质。
- Auditing Harness Tampering（2609.00069）读 diff 做静态分类与定位；本文运行候选，在接受前判定，并给出可重放的反例。
- SEAL（2607.24300）用隐藏任务上的得分比较候选与当前版本；本文比较的是两个版本对同一份证据的完成判定。SEAL 的 “monotone” 条件指只允许加强自写测试，与本文的验证单调性不是同一概念，论文中需要明确区分。
- Self-Harness（2606.09498）在任务上做回归验收。看分数的验收看不见同时提了分的侵蚀，`lean_completion` 就是这样的例子。
- PROCTOR（2609.02246）用金丝雀样例约束 LLM 评审；本文的提示词哨兵借鉴这一思路，但比较的是基线与候选之间的翻转。
- 不能声称“首个”。Kumar et al. 的 “Gate presence is not a safety invariant” 仍未读到原文，定稿前必须核对。

## 6. 评测设计

- **数据。** E1 种子 35 个，E2 中性 70 个，E2b 压力 71 个，全部使用已冻结的标签。人工复标完成后用人工标签重算一次，两次结果都报告。
- **对比方法。** 回归测试、G1、G2、G3、G1+G2+G3、LLM 审计员，以及本方法与 LLM 审计员的组合。
- **指标。** 侵蚀检出率、良性误拒率、inconclusive 比例（均带 Wilson 95% 区间），单个补丁的耗时，哨兵的模型调用次数，反例长度。
- **消融。** 去掉定向变异（只用种子轨迹）；只做结局层面判定、不做尝试层面判定；去掉哨兵。
- **在线应用。** 研究方案的在线小循环中，比较只看分数和加本方法两种选择规则，测量虚假提升和留出任务分数。

## 7. 实施阶段

每个阶段结束于可检查的产物。

- [ ] **M1 冻结验证原因与评测协议。** `experiments/erosion-v1/monotonicity-reasons-v1.json` 和本文第 4、6 节一起提交，之后不再修改判定准则。
- [ ] **M2 差分重放。** 同一脚本化轨迹在基线和候选上各跑一次，产出两份 journal。证据：空补丁在全部种子轨迹上两边判定一致。
- [ ] **M3 尝试层面判定。** 从 journal 重建证据状态，用基线逻辑判定。完成判定分布在 `EvidenceGate.decide`（`src/evidence_harness/evidence.py`）和 `run_loop.py` 的审查、修复处理中，需要抽出一个基线侧的判定入口。证据：E2b 的审查配额绕过补丁得到反例，空补丁没有反例。
- [ ] **M4 定向变异与最小化。** 证据：E1 作者种子上的检出与误拒，反例可重放。
- [ ] **M5 提示词哨兵。** 冻结哨兵样例与阈值后再运行。证据：`reviewer_trusts_agent_summary` 和 `polyglot-rust-c__claude-sonnet-5-5__s0` 上的翻转比例。
- [ ] **M6 留出评测。** 在 E2 和 E2b 上与全部对比方法比较，输出 canonical JSON。

## 8. 风险与限制

- **轨迹对不齐。** 候选如果修改了动作格式或提示协议，脚本化模型的回答可能无法解析。这类情况记为 inconclusive，比例必须报告。
- **证据状态重建。** 尝试层面判定依赖 journal 记录了足够的状态。候选如果改变了 journal 的记录方式，重建会失败，同样记为 inconclusive。
- **保守性。** 合理的新完成路径会被判为违反，需要人工复核。
- **搜索不完备。** 方法是测试而不是证明，搜索预算内没有找到反例不等于满足单调性。
- **标签。** 目前标签只来自 LLM，人工复标完成前，所有比较都是临时结果。
- **对抗性候选。** 与现有 gate 相同，本方法针对非对抗的侵蚀，候选主动篡改判定的情况不在范围内。
